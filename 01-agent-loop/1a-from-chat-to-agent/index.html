    Урок 1: От чатбота к агенту

    Разбор курса «Build Your Own AI Coding Agent Harness» от Vercel Academy (автор — Joel Hooks). Перевод и адаптация на русский.

    Что узнаем в этом уроке

    Мы начнём с самого простого: возьмём обычный AI-чатбот — тот, что умеет отвечать на вопросы и объяснять код, — и превратим его в агента: существо, которое действует, а не рассказывает. Ключ к превращению — один-единственный инструмент read, который даёт модели возможность открыть реальный файл на диске.

    По ходу урока мы: - поймём, почему чатбот без инструментов ведёт себя как «самый самоуверенный стажёр»; - познакомимся с ToolLoopAgent из AI SDK v6 — циклом «думай → действуй → наблюдай»; - напишем инструмент read с Zod-схемой входа; - научимся ограничивать вывод инструмента, чтобы не засорять контекст модели.

    Проблема — что не работает и почему

    Чатбот — это модель, которая получает текст и возвращает текст. Больше у неё ничего нет. Когда ты просишь её сделать что-то реальное — «найди, где в проекте ломается импорт», «посмотри, что написано в package.json» — она не может это сделать, потому что у неё нет рук. Файлов она не видела.

    Но модель не говорит «я не могу». Она обучена быть полезной, поэтому она выдумывает правдоподобный ответ:

    👤 Пользователь: «Посмотри, какая версия React у нас в package.json»

    🤖 Чатбот: «Судя по вашему проекту, вы используете React 18. Обычно в таких проектах зависимости выглядят так: "react": "^18.2.0"...»

    Проблема в том, что этот ответ — чистая конфабуляция. Модель не открывала package.json. Она произвела наиболее вероятный ответ на основе статистики, а не факта. Это и есть «самый самоуверенный стажёр»: он говорит уверенно, гладко, с деталями — но никогда не смотрел в код, потому что не умеет.

    Пока речь об абстрактных вопросах («объясни, что такое closure»), это не страшно — модель отвечает из своих знаний. Но как только мы хотим, чтобы она работала с реальным проектом, отсутствие инструментов становится фатальным:

    • она не может прочитать файл;
    • не может найти, где объявлена функция;
    • не может проверить, прошли ли тесты;
    • и — самое опасное — не признаётся в этом, а генерирует вымышленный ответ.

    Вывод: знания модели ≠ доступ к твоему проекту. Чтобы перейти от «рассказывает» к «делает», нужно дать модели инструмент.

    Решение — подход с полным кодом

    Один инструмент меняет всё

    Инструмент (tool) — это функция, которую модель может вызвать во время разговора. Вместо того чтобы выдумать содержимое файла, модель вызывает read("package.json"), получает реальный текст — и отвечает уже на основе факта.

    Цикл агента выглядит так:

    1. Пользователь ставит задачу
2. Модель решает: нужно ли ей что-то узнать? → вызывает инструмент read
3. Инструмент читает файл и возвращает текст
4. Модель видит результат и либо вызывает ещё инструмент, либо отвечает
5. Повторяем шаги 2–4, пока задача не решена

    Этот цикл «думай → действуй → наблюдай» в AI SDK v6 уже реализован за нас — классом ToolLoopAgent. Нам остаётся только: подключить модель, написать инструмент и задать стоп-условие.

    Полный код: импорты

    Начнём с импортов. Обрати внимание: ToolLoopAgent, tool и stepCountIs приходят из пакета ai (это Vercel AI SDK). Схему входа инструмента описываем через Zod — отдельную библиотеку валидации.

    import { ToolLoopAgent, stepCountIs, tool } from "ai";
import { z } from "zod";
import { readFileSync } from "node:fs";
import { resolve } from "node:path";
    • ToolLoopAgent — класс агента, который крутит цикл «вызов инструмента → результат → снова вызов».
    • tool — фабрика, которая оборачивает нашу функцию в инструмент с описанием и схемой.
    • stepCountIs — стоп-условие: «остановись после N шагов».
    • z — Zod для описания входных параметров.
    • readFileSync, resolve — стандартные средства Node.js для чтения файлов.

    Инструмент read с Zod-схемой

    Инструмент read читает файл из рабочей директории и возвращает его содержимое как текст. Три ключевые части: description (что читает модель), inputSchema (какие параметры принимает, через Zod) и execute (что реально выполняется).

    const MAX_READ_LINES = 500;

const read = tool({
  description: `Read a file from the working directory and return its contents as text.
WHEN TO USE: reading a known file path, inspecting source code,
  checking configuration, understanding a specific file.
WHEN NOT TO USE: searching across many files for a pattern (use grep instead).
Output is capped at ${MAX_READ_LINES} lines. If the file is longer,
  you will see a truncation notice and can read further by requesting
  a specific line range.`,
  inputSchema: z.object({
    path: z
      .string()
      .describe("Path to the file, relative to the working directory"),
  }),
  execute: async ({ path }) => {
    const fullPath = resolve(process.cwd(), path);
    const lines = readFileSync(fullPath, "utf-8").split("\n");
    const capped = lines.slice(0, MAX_READ_LINES);
    const truncated = lines.length > MAX_READ_LINES;
    return (
      capped.join("\n") +
      (truncated
        ? `\n... (truncated: showing first ${MAX_READ_LINES} of ${lines.length} lines)`
        : "")
    );
  },
});

    📝 Перевод промта (поле description — это то, что читает модель, чтобы понять, когда и как использовать инструмент):

    «Прочитай файл из рабочей директории и верни его содержимое как текст.

    КОГДА ИСПОЛЬЗОВАТЬ: чтение известного пути к файлу, изучение исходного кода, проверка конфигурации, понимание конкретного файла.

    КОГДА НЕ ИСПОЛЬЗОВАТЬ: поиск паттерна по множеству файлов (используй grep вместо этого).

    Вывод ограничен 500 строками. Если файл длиннее, ты увидишь уведомление об обрезке и сможешь прочитать дальше, запросив конкретный диапазон строк.»

    Почему 500 строк — это важно. Уже на первом инструменте мы закладываем принцип bounded output — ограниченного вывода. Каждый результат инструмента попадает в контекст модели и остаётся там навсегда (в рамках сессии). Если read вернёт файл на 10 000 строк, эти 10 000 строк навсегда займут место в памяти агента. 500 строк достаточно, чтобы понять структуру любого файла; остальное агент может добрать пагинацией.

    Обрати внимание на вторую часть: при обрезке мы возвращаем видимое сообщение ... (truncated: showing first 500 of 10532 lines). Модель видит, что результат неполный, и понимает, что нужно запросить следующую порцию. Инструмент, который молча усекает, обманывает модель — она думает, что видит весь файл.

    Собираем агента

    Теперь создаём сам ToolLoopAgent. Ему нужно три вещи: модель, системная инструкция и набор инструментов.

    const agent = new ToolLoopAgent({
  model: "anthropic/claude-haiku-4-5",
  instructions: `You are a coding agent working in the current directory.

# Agency
- USE your tools. Read files, then answer from what you actually saw.
- Do NOT explain what you WOULD do. Actually do it.
- If you have not read a file, do not claim to know its contents.`,
  tools: { read },
  stopWhen: stepCountIs(10),
});

    📝 Перевод промта (системная инструкция instructions):

    «Ты — агент по работе с кодом в текущей директории.

    # Действие - ИСПОЛЬЗУЙ свои инструменты. Читай файлы, затем отвечай, исходя из того, что реально увидел. - НЕ объясняй, что бы ты СДЕЛАЛ. Сделай это на самом деле. - Если ты не читал файл, не утверждай, что знаешь его содержимое.»

    Разберём каждую часть:

    • model — строка "anthropic/claude-haiku-4-5". Это маршрут через AI Gateway: провайдер + имя модели. Haiku — быстрая и дешёвая модель, идеальна для старта.
    • instructions — системный промпт. Обрати внимание на секцию # Agency: мы прямо запрещаем модели объяснять вместо того, чтобы делать. Это ключевая строчка — она превращает «рассказчика» в «деятеля».
    • tools: { read } — объект инструментов. Ключ read — это имя, по которому модель будет вызывать инструмент.
    • stopWhen: stepCountIs(10) — стоп-условие. Агент остановится после 10 шагов (шаг = один вызов инструмента или один ответ), даже если модель хочет продолжать. Это страховка от бесконечного цикла.

    Запускаем агента

    У агента есть метод run, который принимает текст задачи и возвращает текстовый ответ:

    const answer = await agent.run(
  "Read package.json and tell me the exact version of React."
);

console.log(answer.text);

    Теперь модель реально читает файл. Сравни с чатботом: там модель угадывала версию, здесь — вызывает read, видит "react": "^18.2.0" и отвечает фактом. Разница — одна строчка конфигурации tools: { read }, но поведение качественно другое.

    Ключевые выводы

    • Чатбот = модель без рук. Он не может читать файлы, поэтому выдумывает правдоподобные ответы. Это не «враньё», а статистическая конфабуляция — модель обучена быть уверенной.
    • Один инструмент превращает чатбота в агента. read даёт модели доступ к реальному состоянию проекта — и ответы становятся основанными на фактах.
    • ToolLoopAgent — готовая реализация цикла. «Думай → действуй → наблюдай» уже написана в AI SDK v6; мы только подключаем модель, инструменты и стоп-условие.
    • description — это инструкция для модели. Она решает, когда вызывать инструмент, читая это поле. Пиши его как для коллеги-стажёра: что делает, когда использовать, когда не использовать.
    • Ограничивай вывод с первого дня. Лимит в 500 строк — не косметика, а защита контекста: каждый результат инструмента остаётся в памяти агента навсегда.
    • Обрезка должна быть видимой. Модель обязана знать, что видит не весь файл, — иначе она примет частичный результат за полный.
    • stepCountIs — страховка. Без стоп-условия агент может зациклиться и жечь токены бесконечно.

    Попробуй сам

    1. Запусти чатбота без инструментов. Создай агента с пустым tools: {} и спроси: «Какая версия React в package.json?» Заметь, как уверенно модель выдумывает ответ.

    2. Добавь read и сравни. Подключи инструмент read и задай тот же вопрос. Обрати внимание: теперь в ответе — реальная версия, а в логах виден вызов инструмента.

    3. Проверь лимит. Создай файл на 2000 строк и попроси агента прочитать его. Убедись, что в ответе появилось сообщение об обрезке (... truncated), и что модель упоминает его, а не игнорирует.

    4. Поэкспериментируй со стоп-условием. Поменяй stepCountIs(10) на stepCountIs(2) и дай задачу, требующую чтения нескольких файлов. Посмотри, как агент останавливается на полпути — и почему это лучше, чем бесконечный цикл.

    5. Убери секцию # Agency из инструкции. Дай задачу «прочитай файл X и перескажи». Сравни, как меняется поведение: модель снова начинает «объяснять, что бы сделала», вместо того чтобы делать.
