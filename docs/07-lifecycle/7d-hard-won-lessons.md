# Урок 7d: Пять проблем из продакшна — выученные уроки

Машина состояний, снимки и долговечные workflow красиво выглядят на бумаге. Но продакшн ломает их пятью конкретными способами — каждый из которых всплыл только на реальных пользователях, реальных переподключениях и реальных сбоях провайдера. Этот урок — сборник выученных уроков, по одному на каждую проблему.

---

## Проблема

Теоретическая модель жизненного цикла предполагает, что хэндлы не устаревают, данные о сроке не протухают, опрос не мешает, а состояние всегда согласовано. Реальность нарушает каждое из этих предположений.

---

## Решение с кодом: пять проблем и пять исправлений

### Проблема 1: устаревшие хэндлы после переподключения

Хэндл песочницы (клиентская ссылка на ВМ) **переживает** отключение пользователя. Но сессия **внутри** хэндла — нет: ВМ за это время могла быть остановлена или пересоздана. Хэндл выглядит рабочим, но команды через него **уходят в никуда** — тихо, без ошибок.

**Исправление: echo probe.** Перед использованием хэндла — проверить его живой командой; при неудаче — восстановить из снимка.

```typescript
async function isAlive(sandbox: CloudSandbox): Promise<boolean> {
  try {
    const { exitCode } = await sandbox.exec("echo probe");
    return exitCode === 0;
  } catch {
    return false;   // хэндл мёртв — команды уходят в никуда
  }
}

async function getUsableSandbox(sandboxId: string, snapshotId: string) {
  const current = await getHandle(sandboxId);
  if (await isAlive(current)) return current;
  // Хэндл устарел → восстанавливаем из снимка
  return restore(snapshotId, config);
}
```

### Проблема 2: устаревшие данные о сроке

Песочница сообщает `expiresAt` **при создании**. Если закэшировать это значение, ты будешь проверять устаревшие данные: ВМ могла быть пересоздана из снимка, и её срок жизни теперь другой. Кэш говорит «ещё 3 часа», а на самом деле — «уже истекла».

**Исправление: всегда получать свежие данные от провайдера.**

```typescript
// НЕ так — кэш протухает
// const expiresAt = sandbox.expiresAt;  // значение на момент создания

// А так — каждый раз спрашиваем провайдера
async function getFreshExpiry(sandboxId: string): Promise<number> {
  const status = await provider.getSandbox(sandboxId);   // свежий запрос
  return status.expiresAt;
}
```

### Проблема 3: опрос сбрасывает неактивность

Lifecycle-workflow опрашивает статус каждые 30 секунд («жива ли?», «не пора ли гибернировать?»). Если **опрос считается активностью**, окно неактивности никогда не закрывается — опрос сам держит песочницу «активной» вечно. Гибернация не наступает, экономии нет.

**Исправление: трекер активности учитывает только пользовательские события.**

```typescript
type ActivityEvent =
  | { kind: "user_message" }
  | { kind: "tool_call" }
  | { kind: "file_change" };

// Опрос статуса сюда НЕ входит — иначе окно неактивности не закроется
function recordActivity(event: ActivityEvent) {
  lastActivityAt = Date.now();
}

function isIdleBeyondWindow(now: number, windowMs: number): boolean {
  return now - lastActivityAt >= windowMs;
}
```

### Проблема 4: петли автовозобновления

Пользователь переподключается → песочница возобновляется из снимка → lifecycle-workflow проверяет → «активности нет» → гибернизация → пользователь снова переподключается → … бесконечный цикл. Каждое переподключение запускает restore, а отсутствие активности тут же гасит его обратно.

**Исправление: автоматическое возобновление только при первом входе.**

```typescript
let hasResumedThisSession = false;

async function onUserConnect(sandboxId: string, snapshotId: string) {
  if (hasResumedThisSession) {
    // Это НЕ первое подключение — не трогаем состояние.
    // Пусть песочница остаётся в гибернации, а не мечется туда-сюда.
    return getCurrentStatus(sandboxId);
  }
  hasResumedThisSession = true;
  return restore(snapshotId, config);
}
```

### Проблема 5: расхождение состояния

Состояние песочницы живёт в **трёх местах**: API провайдера, ваша БД и локальный кэш клиента. Они расходятся: клиент думает «active», БД говорит «hibernating», а провайдер — «уже удалена». Чьему слову верить?

**Исправление: API провайдера — единственный источник истины (source of truth).**

```typescript
// Все решения о жизненном цикле принимаются по данным ПРОВАЙДЕРА.
// БД и кэш — это кэши, они могут врать.
async function getAuthoritativeState(sandboxId: string): Promise<SandboxState> {
  const remote = await provider.getSandbox(sandboxId);   // источник истины
  // Обновляем локальный кэш из свежих данных, а не наоборот
  cache.set(sandboxId, remote.state);
  return remote.state;
}
```

---

## Ключевые выводы

- **Все пять проблем — про «протухшее» состояние:** устаревший хэндл, устаревший `expiresAt`, неверный счёт активности, лишний restore, расхождение источников.
- **Универсальный приём — не доверять кэшу, спрашивать источник:** свежий `echo probe` вместо веры в хэндл, свежий `expiresAt` вместо кэша, свежее состояние от провайдера вместо локального.
- **Опрос ≠ активность.** Это самая коварная ловушка: сам механизм проверки незаметно саботирует то, что проверяет.
- **Петли возникают из симметрии:** переподключение запускает restore, а тишина — гибернацию; если обе реакции безусловны, они зацикливаются. Разорви цикл условием «только первый раз».
- **Один источник истины.** Когда три хранилища расходятся, правит то, что ближе к реальности — API провайдера.

---

## Попробуй сам

1. Симулируй устаревший хэндл: сохрани хэндл, «останови» ВМ, затем вызови через старый хэндл команду. Убедись, что `echo probe` ловит мёртвый хэндл.
2. Закэшируй `expiresAt`, пересоздай песочницу из снимка и посмотри, как кэш врёт о сроке. Замени на свежий запрос.
3. Добавь опрос статуса в трекер активности и убедись, что окно неактивности перестаёт закрываться. Убери опрос.
4. Реализуй `onUserConnect` без флага `hasResumedThisSession` и понаблюдай петлю restore ↔ hibernate. Добавь флаг.
5. Сделай три хранилища (провайдер, БД, кэш), разведи их в разные состояния и напиши функцию, которая всегда возвращает состояние провайдера.
