# Урок 10b: Стриминг — поток вместо одного ответа

`generate()` ждёт, пока агент закончит **весь** прогон, и только потом возвращает результат. Для длинных задач это плохо: пользователь смотрит на пустой терминал 30 секунд, не зная, работает ли агент, какие инструменты вызывает, что происходит. Стриминг решает это — `agent.stream()` отдаёт события по мере их возникновения.

---

## Проблема

С `generate()` ты видишь только финальный текст. Пока агент работает:

- **Нет видимости прогресса** — пользователь не знает, жив ли агент.
- **Нет видимости инструментов** — неизвестно, какие команды запускаются (а это критично для доверия: что именно агент делает с системой).
- **Кажется, что «зависло»** — длинная пауза без обратной связи.

Для интерактивного опыта нужен **поток событий**: текст по мере генерации, вызовы инструментов по мере выполнения, результаты по мере появления.

---

## Решение с кодом

`agent.stream()` вместо `generate()`. Разница в том, **как** читать результат:

```typescript
// НЕ так — один финальный ответ
// const result = await agent.generate({ prompt });
// console.log(result.text);

// А так — поток событий по мере работы агента
const stream = await agent.stream({ prompt });

for await (const part of stream.fullStream) {
  switch (part.type) {
    case "text-delta":
      // Текст от модели — печатаем сразу в stdout
      process.stdout.write(part.text);
      break;

    case "tool-call":
      // Вызов инструмента — в stderr (не засоряет stdout с ответом)
      console.error(`\n🔧 ${part.toolName}(${JSON.stringify(part.input)})`);
      break;

    case "tool-result":
      // Результат инструмента — превью в stderr
      const preview = String(part.result).slice(0, 100);
      console.error(`   → ${preview}${String(part.result).length > 100 ? "…" : ""}`);
      break;
  }
}
```

> **📝 Комментарий переводчика:**
>
> *`fullStream` — это async-итератор по всем событиям агента. Каждое событие имеет поле `type` (`text-delta`, `tool-call`, `tool-result`, …), по которому мы решаем, куда его направить. Текст — в stdout (это «ответ»), всё остальное — в stderr (это «лог»). Разделение потоков позволяет пользователю перенаправить ответ в файл, не захватывая служебный шум.*

### Рендеринг по типу события

| Событие | Куда | Формат | Зачем |
|---|---|---|---|
| `text-delta` | stdout | как есть | Это сам ответ — его пишем напрямую |
| `tool-call` | stderr | `🔧 имя(вход)` | Видимость того, что агент делает |
| `tool-result` | stderr | превью 100 символов | Результат без дампа в консоль |

Ключевая деталь — **превью в 100 символов** для `tool-result`. Результат grep на 50 совпадений или файл на 500 строк не должен вываливаться в терминал целиком — это и шум, и засорение. Сто символов дают понять, **что** вернулось, без дампа.

```typescript
const MAX_PREVIEW = 100;

function preview(text: unknown): string {
  const s = String(text);
  return s.length > MAX_PREVIEW ? s.slice(0, MAX_PREVIEW) + "…" : s;
}
```

### Таблица рендеринга по инструментам

Разные инструменты возвращают разное — и превью должно это учитывать:

| Инструмент | Что в превью | Пример |
|---|---|---|
| `read` | первые строки файла | `// file header…` |
| `grep` | первые совпадения | `src/dates.ts:42: formatDate…` |
| `bash` | хвост вывода (ошибки в конце) | `…3 failed, 47 passed` |
| `todo` | обновлённый список | `[>] 5e6f7a8b Add User model` |
| `askUser` | заданный вопрос | `Asked: "OAuth or JWT?"` |

Общее правило: **превью должно отвечать на вопрос «что произошло», а не «вот весь вывод»**. Полный результат и так остаётся в контексте агента — в консоль идёт только сигнал.

### Полный пример

```typescript
async function runStreaming(agent: ToolLoopAgent, prompt: string) {
  const stream = await agent.stream({ prompt });

  for await (const part of stream.fullStream) {
    switch (part.type) {
      case "text-delta":
        process.stdout.write(part.text);
        break;

      case "tool-call":
        console.error(`\n🔧 ${part.toolName}(${JSON.stringify(part.input)})`);
        break;

      case "tool-result":
        console.error(`   → ${preview(part.result)}`);
        break;

      case "error":
        console.error(`\n❌ ${part.error}`);
        break;

      default:
        // неизвестные типы — игнорируем, не падаем
        break;
    }
  }
  console.log();  // финальный перевод строки после ответа
}
```

---

## Ключевые выводы

- **`agent.stream()` вместо `generate()`** — получаешь события по мере работы, а не один финальный текст.
- **`fullStream`** — async-итератор событий; каждое имеет поле `type`.
- **Разделение потоков:** `text-delta` → stdout (ответ), `tool-call`/`tool-result` → stderr (лог). Ответ можно перенаправить в файл без служебного шума.
- **Превью 100 символов** для результатов инструментов — сигнал «что произошло», а не дамп.
- **Незнакомые типы событий — игнорируй, не падай** (`default`-ветка): API может добавить новые типы.

## Попробуй сам

1. Запусти того же агента через `generate()` и через `stream()` — сравни ощущение: во втором случае виден прогресс и вызовы инструментов.
2. Убедись, что `text-delta` идёт в stdout, а `tool-call` — в stderr: `node cli.js > out.txt` должен записать в файл только текст ответа.
3. Поиграй с размером превью: 50, 100, 500 символов. Где баланс между информативностью и шумом?
4. Добавь рендеринг для `error`-события и намеренно вызови ошибку инструмента — проверь, что она видна, а не молча проглочена.
5. Проверь `default`-ветку: залогируй неизвестные типы событий и посмотри, какие события SDK реально шлёт, о которых ты не знал.
