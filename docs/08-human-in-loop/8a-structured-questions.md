# Урок 8a: Структурированные вопросы — инструмент askUser

Агенты по умолчанию **не задают вопросов**. Модель, обученная на данных разработчиков, предпочитает «просто разобраться сама» — и на неоднозначной задаче угадывает, вместо того чтобы спросить. «Добавь авторизацию» — и агент молча выбирает OAuth, хотя тебе нужен был JWT. Этот урок — о том, как заставить агента спрашивать, когда это действительно нужно.

---

## Проблема

Даже если добавить инструмент `askUser` в набор, модель будет его **игнорировать** без явной инструкции. Почему? Потому что обучение модели закрепляет паттерн «разработчик сам решает неоднозначности». Инструмент сам по себе ничего не меняет — нужен ещё и **протокол в промпте**, который говорит модели, **когда** спрашивать.

Вторая тонкость: вопрос пользователю — это **пауза** в работе агента. Наивная реализация «заблокировать `execute` и ждать ответа» ломает поток: агент зависает, а ответа может не быть минутами. Нужен асинхронный механизм.

---

## Решение с кодом

Два компонента: инструмент `askUser` и протокол в промпте.

### 1. Инструмент askUser: вопрос + 2–4 варианта

```typescript
import { tool } from "ai";
import { z } from "zod";

const askUser = tool({
  description: `Ask the user a multiple-choice question.
WHEN TO USE: scoping ambiguous tasks, choosing between approaches,
  resolving a missing detail before acting.
WHEN NOT TO USE: you already have enough context to proceed.
DO NOT USE FOR: rhetorical questions or progress updates.`,
  inputSchema: z.object({
    question: z.string().describe("The question for the user"),
    options: z.array(z.string()).min(2).max(4).describe("2 to 4 choices"),
  }),
  execute: async ({ question, options }) => {
    const formatted = options.map((o, i) => `${i + 1}. ${o}`).join("\n");
    console.log(`\nQuestion: ${question}\n${formatted}\n`);
    // КЛЮЧЕВОЕ: execute НЕ ждёт ответа — возвращает строку сразу.
    return `Asked: "${question}"\nOptions:\n${formatted}\n\n(Awaiting user response.)`;
  },
});
```

> **📝 Перевод промта (описание askUser):**
>
> *«Задай пользователю вопрос с выбором из нескольких вариантов.*
> *КОГДА ИСПОЛЬЗОВАТЬ: уточнение неоднозначных задач, выбор между подходами, восполнение недостающей детали перед действием.*
> *КОГДА НЕ ИСПОЛЬЗОВАТЬ: у тебя уже достаточно контекста для продолжения.*
> *НЕ ИСПОЛЬЗОВАТЬ ДЛЯ: риторических вопросов или обновлений о прогрессе.»*

### execute НЕ ждёт ответа — возвращает строку

Обрати внимание: `execute` **сразу** возвращает строку `"(Awaiting user response.)"`, а не блокируется в ожидании ответа. Это осознанное решение:

```typescript
// НЕ так — блокировка: агент зависает, пока пользователь не ответит
// execute: async ({ question, options }) => {
//   const answer = await waitForUserResponse();  // висит минутами
//   return answer;
// }

// А так — асинхронно: вернули строку, агент продолжил/остановился
execute: async ({ question, options }) => {
  // ...
  return `Asked: "${question}"\nOptions:\n${formatted}\n\n(Awaiting user response.)`;
}
```

Асинхронный поток: агент задал вопрос → получил строку-подтверждение → **останавливается** (или ждёт) → пользователь отвечает **отдельным** сообщением → это сообщение входит в контекст как обычный ввод → агент продолжает с учётом ответа. Ответ пользователя — это просто следующее сообщение в диалоге, а не «разморозка» зависшего вызова.

### 2. Протокол в промпте: ищи → спрашивай → действуй

Инструмент без протокола бесполезен. В системный промпт добавляется секция, которая учит модель, **когда** спрашивать:

```typescript
sections.push(`# Handling Ambiguity
When the task is ambiguous or has multiple valid approaches:
1. Search the code or docs to gather context first
2. Use askUser to let the user choose. Do NOT guess.
3. Examples: "add auth" -> ask OAuth or JWT; "set up a db" -> ask Postgres or SQLite

Specific tasks (with file paths, line numbers, or precise instructions) do not
need askUser. Act directly.`);
```

> **📝 Перевод промта (протокол Handling Ambiguity):**
>
> *«Когда задача неоднозначна или имеет несколько подходов:*
> *1. Сначала поищи в коде или документации, чтобы собрать контекст*
> *2. Используй askUser, чтобы пользователь выбрал. НЕ угадывай.*
> *3. Примеры: «добавь авторизацию» → спроси OAuth или JWT; «настрой базу» → спроси Postgres или SQLite*
>
> *Конкретные задачи (с путями к файлам, номерами строк или точными инструкциями) не требуют askUser. Действуй напрямую.»*

Порядок «ищи → спрашивай → действуй» важен: агент сначала собирает контекст (чтобы задать **умный** вопрос), потом спрашивает (только если неоднозначность реальна), потом действует. И сдержка на случай, когда неоднозначности нет.

### Два примера в промпте достаточно

Заметь: в протоколе **два** примера (`"add auth" → OAuth/JWT`, `"set up a db" → Postgres/SQLite`). Этого достаточно. Модели не нужен список из двадцати кейсов — ей нужен **паттерн** «расплывчатая задача → конкретный выбор из вариантов». Два примера задают паттерн, а дальше модель обобщает сама.

---

## Ключевые выводы

- **Агенты не спрашивают по умолчанию** — даже с инструментом `askUser` нужен явный протокол в промпте, иначе модель угадает.
- **Два компонента:** инструмент `askUser` (вопрос + 2–4 варианта) и протокол «ищи → спрашивай → действуй» в системном промпте.
- **`execute` НЕ ждёт ответа** — возвращает строку сразу. Ответ пользователя приходит отдельным сообщением и входит в контекст как обычный ввод.
- **Сначала ищи, потом спрашивай:** агент должен собрать контекст, чтобы задать умный вопрос, а не спрашивать вслепую.
- **Двух примеров в промпте достаточно** — модель ловит паттерн, а не заучивает список.

## Попробуй сам

1. Запусти агента с `askUser`, но **без** протокола в промпте, на задаче «добавь авторизацию». Убедись, что он угадывает вместо вопроса.
2. Добавь протокол «ищи → спрашивай → действуй» и повтори ту же задачу. Теперь агент должен вызвать `askUser` с вариантами OAuth/JWT.
3. Дай конкретную задачу («добавь null-check в `src/auth.ts:42`») и убедись, что агент действует напрямую, без вопроса.
4. Проверь, что `askUser` возвращает строку `"(Awaiting user response.)"`, а не блокируется: замерь время до возврата.
5. Убери примеры из протокола и сравни, насколько хуже модель распознаёт неоднозначность. Верни два примера.
