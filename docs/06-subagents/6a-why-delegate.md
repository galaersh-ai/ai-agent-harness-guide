# Урок 6a: Почему делегировать — три режима отказа одиночного агента

Один агент с полным набором инструментов кажется простым и достаточным: дал ему `read`, `grep`, `bash` — и он всё сделает сам. На маленьких задачах так и есть. Но как только задача вырастает до реальных размеров — «разберись, как устроена авторизация в этом проекте, и добавь поддержку refresh-токенов» — одиночный агент начинает ломаться. Причём не случайно, а тремя **предсказуемыми** способами. Понимание этих трёх режимов отказа — фундамент, на котором строится вся архитектура делегирования.

---

## Проблема

Одиночный агент на задаче из 30+ шагов отказывает в трёх режимах.

### Режим 1: загрязнение контекста

Чтобы «разобраться, как устроена авторизация», агент должен прочитать много файлов: `auth.ts`, `middleware.ts`, `session.ts`, конфиги, тесты… 20 файлов. Каждый прочитанный файл **навсегда** остаётся в контексте — это сотни и тысячи токенов мусора, которые засоряют память и выталкивают из внимания сами инструкции агента.

```
Step 0:  1,200 input tokens   ← промпт + системные инструкции
Step 3:  9,400 input tokens   ← 5 файлов уже прочитаны
Step 8:  31,000 input tokens  ← 12 файлов в памяти
Step 15: 68,000 input tokens  ← исследование съело половину окна
```

К тому моменту, когда агент наконец добирается до **самой работы** (написать код), его контекст уже наполовину занят результатами исследования, которые ему больше не нужны.

### Режим 2: потеря фокуса

Длинная задача — это длинная цепочка шагов. К 30-му шагу агент «устаёт» в буквальном смысле: его внимание расползается. Он замечает опечатку в CSS — исправляет её. Потом видит, что импорт можно переписать красивее — рефакторит. Потом натыкается на старый TODO — берётся и за него.

Исходная задача — «добавить refresh-токены» — забыта. Агент ушёл в сторону и сжигает шаги и токены на постороннюю работу. Это не баг модели, это **свойство длинного авторегрессивного прогона**: чем длиннее цепочка, тем больше вероятность отклонения.

### Режим 3: слишком широкие возможности

У одиночного агента есть всё: он может и читать, и писать, и запускать команды. Во время **исследования** — этапа, когда нужно только понять — он «по доброте душевной» начинает и **менять**: поправил файл, который читал, удалил «лишний» код, переименовал переменную. Исследование, которое должно быть read-only, становится модификацией, и ломает то, что трогать не просили.

> **Суть всех трёх режимов:** одному агенту приходится быть одновременно исследователем, исполнителем и планировщиком. Эти роли конфликтуют. Исследование требует чтения (много контекста), исполнение требует записи (много возможностей), планирование требует ясной головы (несовместимо с засорённым контекстом).

---

## Решение с кодом

Паттерн: **родитель планирует, Explorer исследует, Executor выполняет**.

Вместо одного «агента на все руки» появляется иерархия из трёх ролей:

```
                ┌─────────────────────────┐
                │   Родитель (parent)     │
                │   планирует и решает    │
                └───────────┬─────────────┘
                            │ вызывает инструмент task
              ┌─────────────┴─────────────┐
              ▼                           ▼
     ┌─────────────────┐         ┌─────────────────┐
     │    Explorer      │         │    Executor     │
     │  только чтение   │         │  чтение + запись│
     │  быстрая модель  │         │  сильная модель │
     │  5 шагов         │         │  15 шагов       │
     └─────────────────┘         └─────────────────┘
```

Каждая роль получает **ровно те возможности, которые ей нужны**, и ни одной лишней:

```typescript
// Родитель — НЕ погружается в файлы сам.
// Он планирует, декомпозирует и решает архитектурные вопросы.
const parent = new ToolLoopAgent({
  model: "anthropic/claude-sonnet-4-6",
  instructions: buildSystemPrompt({ /* ... */ }),
  // У родителя есть task, askUser и т.д. — но он не читает файлы напрямую.
  tools: { task: createTaskTool(sandbox, parentTools), askUser },
  stopWhen: stepCountIs(20),
});

// Explorer — исследует. Только чтение, быстрая модель, мало шагов.
const explorer = new ToolLoopAgent({
  model: "anthropic/claude-haiku-4-5",
  instructions: `You are an explorer agent. Investigate and report back concisely.
    Working directory: ${sandbox.workingDirectory}`,
  tools: { read: parentTools.read, grep: parentTools.grep },  // ТОЛЬКО чтение
  stopWhen: stepCountIs(5),
});

// Executor — исполняет. Полные инструменты, но bash ограничен trust-листом.
const executorBash = createBashTool(sandbox, createApproval({
  mode: "delegated",
  trust: ["npm test", "npm run build", "npx tsc"],
}));

const executor = new ToolLoopAgent({
  model: "anthropic/claude-sonnet-4-6",
  instructions: `You are an executor agent. Follow instructions precisely.
    Working directory: ${sandbox.workingDirectory}
    Do NOT ask questions. Do NOT explore beyond what's needed. Execute the task.`,
  tools: { read: parentTools.read, grep: parentTools.grep, bash: executorBash },
  stopWhen: stepCountIs(15),
});
```

> **📝 Перевод промта (Explorer):**
>
> *«Ты — агент-исследователь. Исследуй и дай краткий отчёт. Рабочая директория: …»*
>
> *Explorer не может модифицировать файлы, не может запускать команды, не может спрашивать пользователя. Это ограничение — фича, а не недостаток: он физически не способен отклониться, случайно что-то изменить или «сжечь» проект.*

> **📝 Перевод промта (Executor):**
>
> *«Ты — агент-исполнитель. Следуй инструкциям точно. Рабочая директория: … Не задавай вопросов. Не исследуй сверх необходимого. Выполни задачу.»*

### Как это лечит три режима отказа

| Режим отказа | Как лечит делегирование |
|---|---|
| **Загрязнение контекста** | Explorer читает 20 файлов **в своём** контексте, а родителю возвращает сжатый отчёт. Родитель получает вывод, а не дамп файлов. |
| **Потеря фокуса** | У Executor-а жёсткий лимит шагов (15) и узкая инструкция «не исследуй сверх нужного». Он не успевает отклониться. |
| **Слишком широкие возможности** | Explorer вообще не может писать. Executor может писать, но его `bash` ограничен доверенным списком из трёх команд. |

### Почему это работает

Каждый субагент — это **изолированный контекст с узкой задачей**. Его память не смешивается с памятью родителя. Его ошибки и отклонения не отравляют основной поток. А лимит шагов (`stepCountIs(5)` / `stepCountIs(15)`) — это бюджет, который не даёт субагенту «уйти в разгул».

Родитель при этом остаётся **планировщиком**: он видит картину целиком, принимает архитектурные решения и решает, **кому** делегировать каждую подзадачу. Он не пачкает руки чтением файлов — для этого есть Explorer.

---

## Ключевые выводы

- **Одиночный агент отказывает тремя предсказуемыми способами:** загрязнение контекста (исследование забивает память), потеря фокуса (длинный прогон уводит в сторону), слишком широкие возможности (исследование превращается в модификацию).
- **Роли конфликтуют:** исследование требует чтения, исполнение — записи, планирование — ясной головы. Один агент не может хорошо делать все три.
- **Паттерн:** родитель планирует → Explorer исследует → Executor выполняет. Каждая роль получает ровно свои возможности.
- **Изоляция контекста — главная ценность:** субагент читает 20 файлов в своём контексте и возвращает сжатый отчёт, а не дамп.
- **Ограничения — это фича:** Explorer без записи не может ничего сломать; Executor с trust-листом не может выйти за пределы разрешённого.

## Попробуй сам

1. Возьми задачу из 30+ шагов (например, «найди все использования функции `formatDate` в проекте и замени сигнатуру»). Запусти её на **одном** агенте с полными инструментами. Замерь: сколько шагов до завершения, сколько «посторонних» правок он сделал, насколько вырос контекст.
2. Разбей ту же задачу: сначала Explorer (найди все использования), потом Executor (внеси изменения). Сравни количество шагов и «мусорных» правок.
3. Попробуй дать Explorer-у инструмент `bash` — и посмотри, как быстро он начнёт «по доброте душевной» что-то менять во время исследования. Это наглядная демонстрация, почему исследование должно быть строго read-only.
4. Поэкспериментируй с лимитами шагов: снизь `stepCountIs` у Executor-а до 5 и до 30. Где баланс между «не успел» и «ушёл в разгул»?
