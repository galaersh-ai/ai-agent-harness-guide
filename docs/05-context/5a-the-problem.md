# Урок 5a: Проблема контекста — почему агент забывает

Это первый урок модуля о контексте — и он о **диагнозе**, а не о лечении. Прежде чем обрезать, кешировать и ограничивать, нужно понять, что именно происходит с памятью агента на длинной задаче. Мы научимся **измерять** потребление токенов на каждом шаге — и увидим, что проблема не в том, что «агент тупой», а в том, что контекст переполняется по вполне предсказуемому закону.

## Проблема

Ты даёшь агенту длинную задачу — рефакторинг по нескольким файлам, миграцию, добавление фичи с исследованием кодовой базы. Первые шаги идут отлично. Потом агент начинает вести себя странно:

- Забывает свои же инструкции из системного промпта.
- Выбирает не те инструменты (снова тянется к `bash`).
- Зацикливается на одном действии или начинает галлюцинировать.

Интуитивно кажется, что модель «устала» или «потеряла фокус». На самом деле — это **переполнение контекстного окна**. И чтобы это увидеть, нужно измерять.

## Решение с кодом

Начнём с **измерения**: подключим `onStepFinish` и будем логировать потребление токенов на каждом шаге.

```typescript
import { ToolLoopAgent, stepCountIs } from "ai";

const usageLog: Array<{ step: number; inputTokens: number; outputTokens: number }> = [];

const agent = new ToolLoopAgent({
  model: "anthropic/claude-haiku-4-5",
  instructions,
  tools,
  stopWhen: stepCountIs(50),
  onStepFinish: async ({ usage }) => {
    if (usage) {
      usageLog.push({
        step: usageLog.length,
        inputTokens: usage.inputTokens ?? 0,
        outputTokens: usage.outputTokens ?? 0,
      });
      console.error(
        `[step ${usageLog.length}] input=${usage.inputTokens} output=${usage.outputTokens}`,
      );
    }
  },
});
```

`onStepFinish` — хук AI SDK, который вызывается после каждого шага агента. В нём доступен объект `usage` с количеством входных (`inputTokens`) и выходных (`outputTokens`) токенов этого шага. Мы складываем их в массив и печатаем в stderr (чтобы не смешивать с полезным выводом).

### Что показывает лог

Запусти агента на реальной длинной задаче — и увидишь характерную картину:

```
[step 0]  input=1200 output=180
[step 1]  input=2800 output=150
[step 2]  input=4100 output=200
[step 3]  input=8900 output=170   ← ускоряется
[step 4]  input=9200 output=160
...
[step 30] input=178000 output=140  ← почти упёрлись
```

Два наблюдения:

1. **Входные токены растут линейно** (и с ускорением). Каждый шаг добавляет в контекст результат инструмента — и этот результат **остаётся навсегда**. На шаге N контекст содержит результаты всех предыдущих N−1 шагов.
2. **Выходные токены плоские.** Ответ модели на каждом шаге короткий и стабильный (~150–200 токенов). Это подтверждает: проблема не в том, что модель «разговорилась», а в том, что **вход** неконтролируемо растёт.

### Математика переполнения

Контекстное окно — **200 000 токенов**. При линейном росте входа занятой агент упрётся в потолок за **30–50 шагов**:

```
200 000 токенов ÷ ~4 000–6 000 токенов/шаг ≈ 30–50 шагов
```

Что происходит, когда контекст заполнен:

- **Инструкции выталкиваются из внимания.** Системный промпт (Agency, Guardrails, Verification) — в начале контекста, и при переполнении модель перестаёт его «видеть».
- **Выбор инструментов деградирует.** Без Guardrails возвращается «гравитация bash».
- **Агент зацикливается или галлюцинирует.** Старые результаты вытеснили свежий контекст — модель опирается на обрывки.

### Что НЕ работает

Три интуитивных «решения», которые не решают проблему:

| «Решение» | Почему не работает |
|-----------|--------------------|
| **Надеяться** | Рост входа — детерминированный закон, а не случайность. Не рассосётся. |
| **Сократить шаги** | Лимит шагов не меняет **скорость роста** входа. Ты просто упираешься раньше или позже. |
| **Взять модель больше** | Окно больше — но и задача растёт. Рост входа обгоняет рост окна; к тому же модель дороже. |

Все три варианта лечат **симптом** (или вовсе ничего), а не **причину**. Причина — в том, что контекст накапливает мусор без механизма очистки. Лечение — в следующих уроках: обрезка (5b), ограничение вывода (5c), кеширование (5d).

## Ключевые выводы

- **`onStepFinish` + `usage`** — простой способ измерить потребление токенов на каждом шаге.
- **Входные токены растут линейно** (каждый результат инструмента остаётся навсегда), **выходные — плоские** (~150–200 токенов).
- **Контекст 200K → упор за 30–50 шагов.** Это детерминированный закон, а не «модель устала».
- **При переполнении** выталкиваются инструкции, деградирует выбор инструментов, агент зацикливается/галлюцинирует.
- **Что НЕ работает:** надеяться, сократить шаги, взять модель больше. Всё это лечит не причину (накопление мусора), а симптом.

## Попробуй сам

1. Подключи `onStepFinish` с логированием `usage` и запусти агента на длинной задаче (исследование кодовой базы из 10+ файлов). Построй график `inputTokens` по шагам.
2. Убедись, что `outputTokens` действительно плоский, а `inputTokens` — линейно растущий. Зафиксируй наклон кривой.
3. Спрогнозируй, на каком шаге твой агент упрётся в 200K, по формуле `200000 / (средний вход за шаг)` — и проверь, действительно ли деградация начинается рядом с этой точкой.
4. Попробуй «решение» из списка «не работает» (например, ограничь шаги до 10) и подтверди: рост входа на шаг не изменился, изменился только потолок.
