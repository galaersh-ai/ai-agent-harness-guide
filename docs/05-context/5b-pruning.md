# Урок 5b: Обрезка контекста (pruning)

В прошлом уроке мы увидели: входные токены растут линейно, потому что каждый результат инструмента остаётся в контексте **навсегда**. Лечение — **обрезка (pruning)**: выбрасывать старые пары «вызов инструмента → результат», оставляя только недавние. В AI SDK для этого есть готовый `pruneMessages`, а подключить его — четыре строки через хук `prepareCall`.

## Проблема

Контекст агента на шаге 15 выглядит примерно так:

```
[user prompt]                              ← исходная задача
[assistant + tool_call] → [tool_result]    ← шаг 1, старый
[assistant + tool_call] → [tool_result]    ← шаг 2, старый
...ещё 12 пар...
[assistant + tool_call] → [tool_result]    ← шаг 15, недавний
```

Каждая пара «вызов инструмента → результат» — это десятки тысяч токенов (результаты `read` и `bash` бывают огромными). К шагу 15 большинство этих результатов **уже не нужны**: агент давно перешёл к другим файлам и командам. Но все они по-прежнему отправляются модели на каждом следующем шаге.

Нужно правило: **сохранять исходный промпт и недавние взаимодействия, выбрасывать середину.**

## Решение с кодом

Четыре строки через хук `prepareCall`:

```typescript
import { pruneMessages } from "ai";

const agent = new ToolLoopAgent({
  // ... существующая конфигурация
  prepareCall: async (options) => ({
    ...options,
    messages: options.messages
      ? pruneMessages({
          messages: options.messages,
          toolCalls: "before-last-3-messages",
        })
      : undefined,
  }),
});
```

> **📝 Комментарий:**
>
> *`prepareCall` — хук, который вызывается перед каждым отправлением запроса к модели. Он получает полный запрос, который SDK собирается отправить, и может его модифицировать.*
>
> *`pruneMessages` с параметром `"before-last-3-messages"` удаляет все пары «вызов инструмента → результат», кроме трёх последних. Исходный промпт пользователя всегда сохраняется. Недавние взаимодействия сохраняются. Середина разговора, где копятся результаты инструментов, выбрасывается.*

### Что происходит с контекстом

**До обрезки (на шаге 15):**

```
[user prompt]                              ← сохраняется
[assistant + tool_call] → [tool_result]    ← старое, удаляется
[assistant + tool_call] → [tool_result]    ← старое, удаляется
...ещё 12 пар...                           ← удаляются
[assistant + tool_call] → [tool_result]    ← недавнее, остаётся
[assistant + tool_call] → [tool_result]    ← недавнее, остаётся
[assistant] → [user]                       ← недавнее, остаётся
```

**После обрезки:**

```
[user prompt]                              ← исходный промпт
[assistant + tool_call] → [tool_result]    ← недавнее
[assistant + tool_call] → [tool_result]    ← недавнее
[assistant] → [user]                       ← недавнее
```

### Результат — кривая выходит на плато

Главный эффект: вход перестаёт расти линейно. Вместо бесконечного накопления — **плато**:

```
Step 0:  1,200 input
Step 1:  2,800 input
Step 2:  3,100 input   ← старое отсечено
Step 3:  3,400 input   ← плато
Step 4:  3,200 input   ← остаётся плоским
...
Step 50: 3,400 input   ← агент может работать долго
```

Сравни с прошлым уроком, где к шагу 30 вход был 178 000. Обрезка меняет саму **форму кривой**: из линейного роста в горизонтальную линию. Агент может делать десятки шагов, не упираясь в потолок.

### Две ловушки

Код выше выглядит тривиально, но две детали ломают его, если о них не знать:

1. **Спред `...options` нужно ставить первым.** `prepareCall` получает полные опции, включая `model`, `tools` и `system`. Забытый спред молча их выбрасывает — агент ломается запутанно (например, «теряет» модель или инструменты, без явной ошибки).

2. **Защитить `messages` от `undefined`.** На самом первом вызове SDK даёт поле `prompt`, но не массив `messages`. Вызов `pruneMessages({ messages: undefined })` бросает исключение. Поэтому — тернарник `options.messages ? ... : undefined`.

Обе ловушки — про то, что `prepareCall` получает **весь** запрос и вызывается **всегда**, включая первый вызов. Аккуратный спред и защита от `undefined` — обязательны.

## Ключевые выводы

- **`pruneMessages({ toolCalls: "before-last-3-messages" })`** удаляет все пары «вызов → результат», кроме трёх последних; исходный промпт сохраняется всегда.
- **Подключается через `prepareCall`** — хук, который модифицирует запрос перед отправкой модели.
- **Эффект — плато:** вход перестаёт расти линейно, агент может работать десятки шагов без переполнения.
- **Ловушка 1:** спред `...options` первым — иначе теряются `model`/`tools`/`system`.
- **Ловушка 2:** на первом вызове `messages === undefined` — нужна защита тернарником, иначе исключение.
