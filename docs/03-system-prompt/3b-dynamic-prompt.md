# Урок 3b: Динамический промпт — `buildSystemPrompt(ctx)`

В прошлом уроке системный промпт был **захардкоженной строкой**. Это нормально для первого прототипа: один проект, одна песочница, фиксированный набор инструментов. Но каркас агента должен работать с любым проектом. Как только что-то меняется — другая рабочая директория, другой бэкенд песочницы, субагент с подмножеством инструментов — промпт обязан меняться вместе. Захардкоженная строка этого не вывозит.

В этом уроке мы вынесем промпт в **чистую функцию** `buildSystemPrompt`, которая принимает контекст и возвращает строку.

## Проблема

Представь, что промпт — это одна большая строка где-то в середине кода:

```typescript
const instructions = `You are a coding agent working in: /home/me/project
# Agency
- USE your tools...
Available tools: read, grep, bash

# Guardrails
- Prefer simple, minimal changes...`;
```

Пока всё статично, это работает. Но вот типичные сценарии, которые всё ломают:

1. **Другой проект.** Рабочая директория в промпте зашита как `/home/me/project`. Запустил агента в другой папке — промпт врёт.
2. **Другой набор инструментов.** Субагент-исследователь получает только `read` и `grep` (без `bash`). Но промпт всё ещё говорит «Available tools: read, grep, bash» — модель пытается вызвать `bash`, которого нет.
3. **Другая песочница.** Локальная песочница сменилась на облачную — промпт должен об этом знать, но не знает.
4. **Проектный контекст.** Появился `AGENTS.md` с инструкциями проекта — их надо вставить в промпт, но вставить в захардкоженную строку некуда.

Каждый раз приходится править строку вручную. Это не масштабируется — и, что важнее, промпт **должен быть функцией от окружения**, а не константой.

## Решение с кодом

Создаём файл `src/system.ts` с чистой функцией. Она принимает объект контекста и собирает строку из секций:

```typescript
// src/system.ts

interface PromptContext {
  workingDirectory: string;
  sandboxType: string;        // "local" | "just-bash" | "cloud"
  toolNames: string[];        // какие инструменты реально подключены
  gitBranch?: string;         // текущая ветка (если известна)
  projectContext?: string;    // содержимое AGENTS.md (если есть)
}

function buildSystemPrompt(ctx: PromptContext): string {
  const sections: string[] = [];

  sections.push(
    `You are a coding agent working in: ${ctx.workingDirectory}`
  );

  sections.push(`# Agency
- USE your tools. Read files, search code, run commands, then answer.
- Do NOT explain what you WOULD do. Actually do it.
- Available tools: ${ctx.toolNames.join(", ")}`);

  sections.push(`# Guardrails
- Prefer simple, minimal changes
- Search before creating, and reuse existing patterns
- No new dependencies without asking`);

  if (ctx.gitBranch) {
    sections.push(`- Current branch: ${ctx.gitBranch}`);
  }

  if (ctx.projectContext) {
    sections.push(`# Project Instructions (from AGENTS.md)\n${ctx.projectContext}`);
  }

  return sections.join("\n");
}

export { buildSystemPrompt, type PromptContext };
```

> **📝 Перевод промта:**
>
> *Первая секция (всегда есть):*
> *«Ты — агент по работе с кодом, рабочая директория: ...»*
>
> *Секция Agency («Действие»):*
> *«ИСПОЛЬЗУЙ свои инструменты. Читай файлы, ищи по коду, запускай команды — и только потом отвечай.*
> *НЕ объясняй, что бы ты СДЕЛАЛ. Действуй на самом деле.*
> *Доступные инструменты: ...» — сюда подставляется реальный список `ctx.toolNames` через запятую.*
>
> *Секция Guardrails («Ограничения»):*
> *«Предпочитай простые, минимальные изменения.*
> *Сначала ищи, потом создавай; переиспользуй существующие паттерны.*
> *Никаких новых зависимостей без спроса.»*
>
> *Условная строка про ветку:* *«Текущая ветка: ...» — добавляется только если `gitBranch` задан.*
>
> *Условная секция Project Instructions:* *вставляется целиком из `AGENTS.md`, если файл найден.*

### Секции в массиве, `join` в конце

Обрати внимание на механику: каждая секция — элемент массива `sections`, а в конце — один `join("\n")`. Это даёт три вещи:

- **Порядок гарантирован.** Секции идут ровно в том порядке, в котором их `push`-нули.
- **Условность тривиальна.** Хочешь добавить/убрать секцию — добавь/убери `if`. Не нужно собирать строку конкатенацией с вложенными тернарниками.
- **Читаемость.** Каждая секция — отдельный осмысленный блок кода, а не кусок мега-строки.

### Подключение в коде

```typescript
import { buildSystemPrompt } from "./system";

const instructions = buildSystemPrompt({
  workingDirectory: cwd,
  sandboxType: "local",
  toolNames: Object.keys({ read, grep, bash }),
  projectContext,  // содержимое AGENTS.md или undefined
});

const agent = new ToolLoopAgent({
  model: "anthropic/claude-haiku-4-5",
  instructions,
  tools: { read, grep, bash },
  stopWhen: stepCountIs(10),
});
```

Заметь: список инструментов в промпте (`toolNames`) и список инструментов в агенте (`tools`) теперь **всегда совпадают**, потому что оба берутся из одного источника — объекта инструментов. Раньше это было два места, которые расходились вручную.

### Почему именно чистая функция

| Свойство | Что даёт |
|----------|----------|
| **Тестируемость** | Можно писать assert: при данном контексте промпт содержит нужную секцию |
| **Компонуемость** | Добавлять секции, не трогая остальные |
| **Заменяемость** | Пользователь может подсунуть свой билдер промпта |
| **Детерминированность** | Тот же контекст → тот же промпт; легко дебажить и кешировать |

Чистая функция (без побочных эффектов, результат зависит только от аргументов) — идеальная форма для промпта: её можно проверить юнит-тестом и спокойно переиспользовать в разных местах.

## Ключевые выводы

- **Промпт — функция от окружения.** Он обязан знать рабочую директорию, тип песочницы и реальный список инструментов.
- **`PromptContext` — единственный вход.** `workingDirectory`, `sandboxType`, `toolNames`, опционально `gitBranch` и `projectContext`.
- **Секции в массиве + `join`** — простой способ собирать промпт с условными блоками, сохраняя порядок и читаемость.
- **Чистая функция** тестируема, компонуема, заменяема и детерминирована — в отличие от захардкоженной строки.
- **Один источник правды** для списка инструментов: промпт и агент читают его из одного места.

## Попробуй сам

1. Вынеси текущий промпт в `buildSystemPrompt` и убедись, что агент работает как раньше (рефакторинг без изменения поведения).
2. Напиши юнит-тест: `assert(buildSystemPrompt({...}).includes("# Agency"))` и аналогично для `# Guardrails`.
3. Передай `toolNames: ["read", "grep"]` (без `bash`) и проверь, что строка «Available tools» больше не упоминает `bash`.
4. Добавь условную секцию: если `gitBranch` задан, вставляй «Текущая ветка», иначе не вставляй ничего. Проверь оба пути тестом.
