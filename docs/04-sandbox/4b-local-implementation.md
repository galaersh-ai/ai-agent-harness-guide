# Урок 4b: Локальная реализация песочницы

Интерфейс `Sandbox` из прошлого урока — это контракт. Теперь нужна первая реализация: **локальная песочница**, которая выполняет команды прямо на машине, где запущен агент. Это самая простая реализация — «скучная обёртка» над Node.js `readFileSync` и `execSync`. Но именно её простота — достоинство: она задаёт эталон поведения, по которому сверяются все остальные реализации.

## Проблема

У интерфейса `Sandbox` есть требования, которые локальная реализация должна соблюсти:

1. **Все методы async** — даже если внутри всё синхронно.
2. **`exec` никогда не бросает исключение** — возвращает `{stdout, exitCode}`, потому что падающая команда (`npm test` с упавшими тестами) — это не ошибка программы, а *результат*, который агент должен увидеть.
3. **`stop()` должен существовать** — даже если локально освобождать нечего.

Каждое из этих требований ломается, если просто «взять `execSync` и вернуть». Нужна аккуратная обёртка.

## Решение с кодом

Вся реализация — примерно 15 строк:

```typescript
import { execSync } from "node:child_process";
import { readFileSync } from "node:fs";
import { resolve } from "node:path";
import type { Sandbox } from "./sandbox";

function createLocalSandbox(dir: string): Sandbox {
  return {
    type: "local",
    workingDirectory: dir,

    readFile: async (p) => readFileSync(resolve(dir, p), "utf-8"),

    exec: async (command) => {
      try {
        const stdout = execSync(command, {
          cwd: dir,
          encoding: "utf-8",
          timeout: 30_000,
        });
        return { stdout, exitCode: 0 };
      } catch (e: any) {
        return {
          stdout: e.stdout || e.stderr || e.message || "",
          exitCode: e.status ?? 1,
        };
      }
    },

    stop: async () => {},
  };
}
```

### `readFile` — одна строка

```typescript
readFile: async (p) => readFileSync(resolve(dir, p), "utf-8"),
```

Синхронное чтение, обёрнутое в async. Ключевой момент — `resolve(dir, p)`: путь от агента всегда **относительный** к рабочей директории, а `readFileSync` требует абсолютный. `resolve` склеивает `dir` и `p`, заодно нормализуя `..` и лишние слеши.

### `exec` никогда не бросает

Это сердце локальной реализации. Разберём `try/catch`:

- **Успех:** `execSync` вернул stdout → `{ stdout, exitCode: 0 }`.
- **Падение:** команда завершилась с ненулевым кодом (упавший тест, ошибка сборки). Node.js при этом **бросает исключение**, а stdout/stderr кладёт в объект ошибки. Мы их вытаскиваем: `e.stdout || e.stderr || e.message`, а код выхода — из `e.status` (с fallback на `1`).

Почему это критично: агент, запустивший `npm test`, который упал, **должен увидеть вывод падения**. Если бы `exec` пробрасывал исключение, инструмент `bash` получил бы throw вместо результата — и агент либо выдумал бы вывод, либо сломался. Возвращая `{stdout, exitCode}` даже для падений, мы честно передаём агенту: «команда упала, вот её вывод, вот код».

### `stop()` — пустая async-функция

```typescript
stop: async () => {},
```

Локальной песочнице освобождать нечего — нет виртуальной машины, нет сетевых ресурсов. Но метод **обязан существовать**, потому что интерфейс `Sandbox` его требует, и вызывающий код (жизненный цикл агента) будет вызывать `await sandbox.stop()` в любом случае. Пустая функция — честная реализация «нечего делать».

### Ограничения и таймаут

Обрати внимание на `timeout: 30_000` в `execSync`. Это защита от зависших команд. Но это **грубая** защита — таймаут просто убивает процесс. Настоящая изоляция (лимиты CPU, памяти, сети) здесь отсутствует: локальная песочница — это «та же машина, без стенок». Подробнее о компромиссах — в уроке 4d.

## Ключевые выводы

- **Локальная песочница — ~15 строк**: две синхронные обёртки + пустой `stop()`.
- **`readFileSync` / `execSync` обёрнуты в async** — реализация соблюдает async-контракт интерфейса.
- **`exec` никогда не бросает**: `try/catch` превращает падение команды в `{stdout, exitCode}` — агент видит вывод упавших тестов, а не исключение.
- **Код выхода из `e.status ?? 1`**, вывод — из `e.stdout || e.stderr || e.message`.
- **`stop() = async () => {}`** — метод обязан существовать, даже если освобождать нечего.
- **`resolve(dir, p)`** превращает относительный путь агента в абсолютный для `readFileSync`.

## Попробуй сам

1. Реализуй `createLocalSandbox` и проверь: `await sandbox.exec("echo hello")` возвращает `{stdout: "hello\n", exitCode: 0}`.
2. Запусти падающую команду `await sandbox.exec("exit 3")` и убедись, что возвращается `{stdout: "", exitCode: 3}`, а не бросается исключение.
3. Запусти команду, которой нет: `await sandbox.exec("definitely-not-a-command")` — проверь, что в `stdout` попало сообщение об ошибке из `e.message`.
4. Попробуй `await sandbox.readFile("../secret.txt")` и убедись, что `resolve` не даёт выйти за пределы рабочей директории так, как ты ожидаешь (затем подумай, нужна ли здесь защита).
