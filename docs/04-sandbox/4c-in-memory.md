# Урок 4c: In-memory песочница (just-bash)

Локальная песочница из прошлого урока выполняет команды прямо на твоей машине — а значит, агент с правом запускать `bash` может стереть что угодно. Хочется изоляции, но без разворачивания полноценной виртуальной машины. Решение — **in-memory файловая система с copy-on-write**: инструмент `just-bash` виртуализирует ФС в памяти. Агент «читает» с реального диска, но все «записи» происходят в виртуальный слой поверх — оригинал не трогается. В этом уроке мы подключим `just-bash` как ещё одну реализацию `Sandbox`.

## Проблема

Две крайности, между которыми нужна золотая середина:

- **Локальная песочница** — быстро и бесплатно, но **ноль изоляции**. `rm -rf` выполнится по-настоящему.
- **Облачная песочница** — полная изоляция, но **сетевая задержка и поминутная оплата**.

`just-bash` закрывает разрыв: это **in-memory виртуальная ФС с copy-on-write**. Идея:

- **Чтение** идёт с реального диска (быстро, данные настоящие).
- **Запись** попадает в виртуальный слой в памяти, а не на диск.
- При остановке песочницы виртуальный слой просто **утилизируется** — все изменения исчезают, оригинал нетронут.

Но у `just-bash` есть хитрое поведение, которое ломает наивную реализацию. О нём — ниже.

## Решение с кодом

Подключаем `just-bash` как реализацию интерфейса `Sandbox`:

```typescript
import { JustBashSandbox } from "just-bash";

const MOUNT = "/home/user/project";  // виртуальная точка монтирования

async function createJustBashSandbox(dir: string): Promise<Sandbox> {
  const jb = await JustBashSandbox.create({ overlayRoot: dir });

  return {
    type: "just-bash",
    workingDirectory: dir,

    readFile: async (p) => jb.readFile(`${MOUNT}/${p}`),

    exec: async (command) => {
      const cmd = await jb.runCommand(command, { cwd: MOUNT });
      const finished = await cmd.wait();
      return { stdout: await cmd.output(), exitCode: finished.exitCode };
    },

    stop: async () => {},  // при остановке виртуальная ФС утилизируется
  };
}
```

### Ловушка `overlayRoot`: монтируется в `/home/user/project`, а не в `/`

Это главная ловушка `just-bash`, о которую спотыкаются все. `JustBashSandbox.create({ overlayRoot: dir })` монтирует твою директорию **не в корень** виртуальной ФС, а в фиксированный путь `/home/user/project`.

Что это значит на практике:

- Ты передал `overlayRoot: "/home/me/myproject"`.
- Внутри виртуальной ФС твои файлы оказались по пути `/home/user/project/...`, а **не** по `/home/me/myproject/...`.
- Если ты попытаешься читать `/home/me/myproject/package.json` — получишь «файл не найден», потому что внутри песочницы такого пути нет.

Поэтому каждый путь должен проходить через константу `MOUNT`:

```typescript
const MOUNT = "/home/user/project";
readFile: async (p) => jb.readFile(`${MOUNT}/${p}`),
//                            ^^^^^^^^ не забыть префикс
```

И для `exec` — рабочая директория тоже `MOUNT`, а не `dir`:

```typescript
exec: async (command) => {
  const cmd = await jb.runCommand(command, { cwd: MOUNT });
  //                                              ^^^^ не dir
  ...
}
```

Константа `MOUNT` — не магическая строка, которую можно захардкодить по месту. Это **единственный источник правды** о точке монтирования: измени её в одном месте, и все пути обновятся. Захардкоженный `/home/user/project` в трёх местах — это три места, которые разъедутся.

### Отличия `exec` от локальной реализации

Обрати внимание: `just-bash` не даёт синхронного `runCommand`. Нужно три шага:

```typescript
const cmd = await jb.runCommand(command, { cwd: MOUNT }); // запуск
const finished = await cmd.wait();                        // дождаться завершения
return { stdout: await cmd.output(), exitCode: finished.exitCode };
```

Это реально async-API: команда запускается, мы ждём её завершения, потом забираем вывод. Локальная реализация могла обернуть синхронный `execSync` в async; здесь асинхронность — не обёртка, а суть.

### Переключатель песочницы

Теперь у нас две реализации. Выбор — через переменную окружения:

```typescript
const sandboxType = process.env.SANDBOX || "local";

const sandbox =
  sandboxType === "just-bash"
    ? await createJustBashSandbox(cwd)
    : createLocalSandbox(cwd);
```

Заметь два момента:

1. **`createJustBashSandbox` — async** (возвращает Promise), потому что `JustBashSandbox.create` асинхронный. Локальная — синхронная. Поэтому в тернарнике стоит `await` перед веткой just-bash.
2. **Всё, что ниже (инструменты, агент, промпт) — одинаково** для любого бэкенда. Это и есть выигрыш от единого интерфейса из урока 4a: смена среды — одна строка конфигурации, а не переписывание инструментов.

```bash
# запуск с локальной песочницей (по умолчанию)
node agent.js

# запуск с in-memory песочницей
SANDBOX=just-bash node agent.js
```

## Ключевые выводы

- **`just-bash` — in-memory ФС с copy-on-write**: чтение с диска, запись в виртуальный слой, при остановке всё утилизируется.
- **Ловушка `overlayRoot`:** директория монтируется в `/home/user/project`, **не в `/`**. Каждый путь обязан проходить через константу `MOUNT`.
- **`MOUNT` — единственный источник правды** о точке монтирования; и для `readFile` (префикс пути), и для `exec` (`cwd: MOUNT`).
- **`exec` у just-bash реально async**: `runCommand` → `wait()` → `output()`, три шага.
- **Переключатель `process.env.SANDBOX`** меняет бэкенд одной строкой; всё остальное в каркасе одинаково.
- **`createJustBashSandbox` async**, локальная — синхронная; тернарник учитывает это через `await`.

## Попробуй сам

1. Подключи `just-bash` и прочитай файл из проекта через `sandbox.readFile("package.json")` — сначала без префикса `MOUNT`, потом с ним. Убедись, что без `MOUNT` получаешь «файл не найден».
2. Запиши файл внутри just-bash-песочницы (`echo "x" > newfile.txt`), прочитай его обратно — затем останови песочницу и проверь, что на реальном диске файла нет.
3. Переключи `SANDBOX=just-bash` и `SANDBOX=local` и убедись, что агент работает одинаково в обоих режимах.
4. Попробуй в just-bash-песочнице команду `rm -rf` по важному файлу — проверь, что оригинал на диске остался цел (copy-on-write защищает его).
